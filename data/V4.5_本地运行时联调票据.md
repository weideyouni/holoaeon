1. `lms get qwen/qwen2.5-0.5b-instruct --gguf -y` → `Failed to resolve artifact`（短名解析不到）。
2. `lms get https://huggingface.co/Qwen/Qwen2.5-0.5B-Instruct-GGUF --gguf -y` → 长时间停在 `Resolving download plan...`，`TaskStop` 主动停掉。
3. `Invoke-WebRequest https://huggingface.co/api/models/Qwen/Qwen2.5-0.5B-Instruct-GGUF` → **200 / len=7201**，证明不是网络问题。
4. 直连下载 `.../resolve/main/qwen2.5-0.5b-instruct-q4_k_m.gguf` → **468.6 MB** 落到 `C:\Users\Administrator\.lmstudio\models\Qwen\Qwen2.5-0.5B-Instruct-GGUF\`，`lms ls` 仍只 1 个模型。
5. `lms import <path> --user-repo Qwen/Qwen2.5-0.5B-Instruct-GGUF -y -L` → **`EPERM: operation not permitted, mkdir 'D:\'`**；把文件改放 `D:\Qwen\Qwen2.5-0.5B-Instruct-GGUF\` 再 import，仍是同一 EPERM——根因是 `downloadsFolder="D:\"` 指向盘根，导入器要在盘根建目录。
6. `lms load <path>` → 只接受已索引的 model-key，路径不入索引，仍提示 `No models are currently loaded`。

**结论**：对话模型无法在本批内进入 LM Studio 索引（需在 LM Studio 界面把模型目录改到有效路径并重扫，属**你的应用配置**，本 Agent 不擅自改）。因此本批的真调用落在**已就绪的本地端点**上。
