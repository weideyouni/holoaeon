# B4 康复域试点 20 例 · 票据

`pilot_id = SG-B4-REHAB-PILOT-20-V1`
产出：`data/rehab_pilot_20.json`（20 例契约实例 + 4 条负例探针）
构建：`scripts/gen_rehab_pilot.py`（确定性，`--check` 复跑字节一致）
判据：`scripts/check_rehab_pilot.py`（R1–R9）→ `reports/b4_rehab_pilot_check.json`
单测：`tests_contract/test_rehab_pilot.py`（7 项，旁挂套件）

## 一、这一批到底做了什么

把 B1b 的契约 v1、B2a 的六机制映射、B2b 的通道与词表分域、B3 的用途标签，第一次
**合成到同一批真实康复场景上**：20 个契约实例，每个都写明来源技能、落到的 ivsa 模块、
走哪条机制、属于哪一域，并逐条过 V1–V8 校验。

**只映射不调用**：本批不 import、不执行 ivsa 任何代码，只生成 JSON 契约。ivsa 侧"接收"
是登记在 `target` 字段里的模块名（已核对为 `ivsa/` 下真实存在的文件），不是真跑。

## 二、20 例的构成（按实算，不按期望）

| 维度 | 分布 |
|---|---|
| 契约域 | general 12 ／ medical 8 |
| 机制 | hebbian_field 11 ／ skin_v6 4 ／ holographic_heartbeat 3 ／ cytoskeleton 2 |
| 通道 lane | read 12 ／ write 8 |
| 技能标签 | 100% 为 B3 判定的 M（方法学） |

`uncovered_mechanisms = ["semantic_bus","meridian"]`：这两个机制在康复域**没有 M 类技能**
（semantic_bus 全库仅 5 条 M 且均非康复域，meridian 仅 1 条 `tensor-dim-dynamic-tuning`）。
本批不硬凑，登记为 B5 语义技能族扩容的输入需求——**这是 B4 给 B5 的真实缺口，不是缺陷**。

## 三、机制不是手写的

每例的 `mechanism` 都从 `data/skill_matrix_index.json` 的索引字段派生（R4 判据比对该字段），
所以"文档比代码更新鲜"这类漂移不可能发生：改索引 → 试点集必须重建，重建后 R4 才可能过。

技能不得是 K/T/X/U：K 是知识源（可检索不可执行）、T 是工具链（只登记不 import）、X 无关、
U 待判。把 K 当可执行方法用，会让试点数字好看但底座是假的，R3 就是拦这个。

## 五、医学红线（本批遵守情况）

- 零剂量：全部 note 无 `mg/ml/毫克/克/日/剂量/用药`（生成器写完自检 + R7 复检）。
  生成过程中确实被 V7 拦过一次：我在 note 里写了"不含处置剂量"，这句说明本身命中了剂量词，
  已改写为"不做处置输出"。
- C0 不写成疗效：所有场景只描述"流程编排/记录/比对/映射"，没有一条写干预效果。
- 急症转 120：medical 域 8 例三红线全为 true（`zero_dose / c0_not_efficacy / emergency_120`）。
- `evidence_class = simulated`：20 例均为模拟试点，不代表真实临床效果。

## 六、可复跑

```bash
python scripts/gen_rehab_pilot.py           # 重建 20 例
python scripts/gen_rehab_pilot.py --check   # 字节一致才退 0
python scripts/check_rehab_pilot.py         # R1–R9
python -m unittest tests_contract.test_rehab_pilot -v
```

判据含义：R1 例数与编号 / R2 契约全过且指纹可复算 / R3 技能必须是 M / R4 机制随索引 /
R5 target 命中 ivsa 白名单 / R6 域分布与医学红线 / R7 剂量词与预算类型 / R8 负例全拒 /
R9 复跑字节一致。
