## 一、这一批解决什么

V4.3 把「四个工程坑」固化成脚本、把 B8 推到「事实包 → 适配层路由」；但**没有一个真实模型后端**。
V4.4-B1 做三件事：

1. **遍历穷举主流模型**：把 19 家 provider、5 种协议族、4 个本地运行时收进一份可判据的目录（含 1 个自定义兜底）；
2. **把请求拼对**：新建 `model_gateway.py`，按协议族产出 `url + headers + body`，**默认全关**；
3. **给出「自己设」的完整路径**：`docs/接入真实模型_配置指南.md` 写清 `BASE_URL / API_KEY / model` 三件套、五种协议差异、本地三家、成本口径、失败降级、回滚。

**为什么是「离线拼请求」而不是「真发请求」**：本机无 provider 凭证、无计费账户，且仓库 AST 红线禁止 `requests/urllib/socket/http`。
硬凑一个「假联网」只会得到假的 `PASS`；因此本批把「能确定的部分」全部做实（协议、字段、开关、占位、判据），
把「需要凭证的部分」交给用户按指南一次性注入。这是用户在 V4.3 就预设的兜底路径，不是降级。

## 五、开启规则（默认全关，两道锁）

```
锁 1：HOLOAEON_REAL_MODELS = "1"          # 总开关，不设则 enabled 恒为 []
锁 2：该 provider 的 *_API_KEY 有值        # 本地运行时 region=local，允许为空
满足两锁 → ModelGateway.attach() 才把 "gw:<provider>" 注册进 ModelAdapter
```

未满足时：`attach()` 返回 `[]`，`ModelAdapter` 里只剩 `fact-pack-local`，事实包链路与 V4.3 完全一致（封缄 `6704fb78e5cb` 不变）。
剂量问句仍先在 `guard` 被拦（`adapter.used=false / reason="guard_blocked"`），**真模型接进来也不改变拦截顺序**。

成本口径：本仓不记账真实费用；`record_usage()` 记的是 simulated。要控预算，用 `route(..., max_cost=你自定阈值)`。

## 六、边界与未做（不冒充）

| 项 | 状态 |
|---|---|
| 真发一次请求 | **未做**。本机无凭证、无计费账户；仓库红线禁网络库。用户按指南注入 env 后在**自己的运行环境**发 |
| 型号可用性校验 | **未做**。目录示例型号随官方变动，本仓不做在线校验 |
| 价目表 | **未做**。`input_cost/output_cost=0.0` 是占位，不是"免费" |
| 计费对账 | **未做**。需用户自己的账单侧核对 |
| 本地运行时联调 | **未做**。仅按公开文档口径拼端点（Ollama `:11434/v1`、vLLM `:8000/v1`、llama.cpp `:8080/v1`、LM Studio `:1234/v1`） |
| 医学边界 | **不变**。不接设备、不出剂量、不做诊断；仿真≠证明 |

**风险提示（用户点名要动的两项）**：
- **凭证**：本仓只存 env 变量名。`A5` 会拦 `sk-` 真值入库；请勿把 key 写进票据/README/回执。
- **计费**：开真模型即产生真实费用。建议先本地运行时（零成本）跑通链路，再按 provider 逐个开、按 `max_cost` 限流。

## 七、写序与复盘（本轮新增教训）

**写序（G9 修正版，照做）**：
```
跑所有会写回执的校验器（v3_gate / verify_v43 / verify_v44 / verify_b8_dual_sync）
→ build_b8_dual_sync.py → build_b9_zip.py → build_b9_closeout.py → five_site_dna.py build
→ 末尾只跑只读校验（five_site verify / verify_b9_closeout / unittest）
```
理由同 V4.3 已记录的那条：校验器自己写 `reports/*.json`，若在建清单之后再跑，`dual_sync.test_11` 与 `five_site verify` 立刻红。

**本轮新增三条**：
1. **A11 天然是"后验判据"**：它要求「回执 `passed==total`」，而回执由本脚本自己写。首跑必然红一次，这是设计而非缺陷——票据先落盘，再复跑即绿。写判据时要把"自指"显式承认，不能靠跳过。
2. **`probe()` 里加新段要防整体失败**：`gateway` 段用 `try/except` 包住，目录缺失时返回 `{"error": ...}` 而不是让 V4.3 的 `verify_v43`（依赖 `probe`）连坐变红。跨批复用同一探针时，新段必须可缺席。
3. **单测里的 `ResourceWarning` 也算红**：`ast.parse(open(...).read())` 未关文件句柄，测试仍 OK 但告警必须清；改 `with open(...) as f`。

**下批建议**：V4.5 可做「本地运行时联调（Ollama 零成本）」——只需用户本地起服务，就能把"真发一条请求"从"未做"变"已做"，且不产生费用；或按用户点名做 gap 卡逐篇核对（动证据等级，需先拍板）。
