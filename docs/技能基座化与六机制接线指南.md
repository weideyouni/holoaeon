## 一、这份文档解决什么问题

豆包 Work 侧已经沉淀了大量技能（运行时口径 1199 条），本仓只认 47 条 `kernel.skills`。
两边不是同一个编号空间，也**不该**合并。过去几次口头说“加载一下”，落到代码里就变成两件事混淆：

1. **机制**（全息心跳 / 细胞骨架 / 皮肤 / 语义通信 / 赫布场 / 经络）——已经在 `holoaeon/` 包里，是代码。
2. **技能**（外部那 1199 条）——是别人的正文与许可，只能**登记**，不能复制。

本文件把这两层分开写清楚：机制怎么调、技能怎么登记、哪些事坚决不做。

## 二、三分钟上手

```python
from holoaeon import Kernel

k = Kernel()
k.register_agent("a1", skills=["summarize", "translate"])
out = k.submit("把这段摘要翻成英文")
print(out["status"], out["results"][0]["matched"])
```

一次 `submit` 会依次穿过：`Bus → Guard(L1–L8) → 选 agent → 技能执行 → Memory → 汇总`。
六机制全部挂在这条链上，不需要单独启动任何服务。

## 三、六机制 → 模块 → 入口（唯一权威表）

| 机制 | 落在哪个模块 | 可用入口 | 工程含义 |
|---|---|---|---|
| 全息心跳 | `holoaeon/scheduler.py` | `Scheduler` / `HeartbeatBody` / `tick` | 节拍同步，确定性步进，不看墙钟 |
| 细胞骨架 | `holoaeon/kernel.py` | `Kernel` / `submit` / `collab` | 结构支撑与门面 |
| 皮肤机制 | `holoaeon/guard.py` | `Guard` / `l1..l8` / `normalize_for_match` | 语义边界，任一 BLOCK 即拦截 |
| 语义通信底座 | `holoaeon/semvec.py`、`fusion_upgrade/semantic_family.py` | `encode` / `similarity` | 向量表示，sin 置换替代随机源 |
| 赫布协作场 | `holoaeon/graph.py` | `AdaptiveGraph` / `observe` / `route` | 共激活增强 + 全局衰减 |
| 经络机制 | `design_vocab/meridian.py`、`fusion_upgrade/three_field.py` | `CHANNELS` / `route` | 四通道分流，通道数固定 4 |

同一张表的机读版是 `data/v5_skill_base_registry.json`；两者不一致时以**代码里的符号**为准，再回来修表。

## 四、三层结构：机制在仓内，技能只登记

- **L0 机制层**（仓内）：上表六个模块，纯标准库，无网络。
- **L1 技能层**（仓内）：47 条，锁死。加一条就会破 `dimension_lock`，所以“加技能”永远不是本仓的动作。
- **L2 声明层**（仓内）：本文件 + `data/v5_skill_base_registry.json`。
- **L3 外部技能层**（仓外）：1199 条运行时技能，只记录族名与数量，`copied_into_repo=false`。

判断一条外部技能能不能进来，只问三个问题：

1. 它是否需要把正文复制进仓？需要 → 不进（许可与归属都不清）。
2. 它是否能被压缩成“接口形状 + 判据”？能 → 写成声明，挂在对应的 `EXT-` 槽位讨论。
3. 它是否要改 25/47/9？要改 → 不进（这是维度锁，不是待办）。

## 五、跨线程调用纪律（七条）

1. 包内不 `import` 任何外部技能目录，也不 `subprocess` 调它们的 CLI（红线会直接红）。
2. 需要外部能力时，走 `model_adapter` / `fusion_upgrade.model_gateway` 的**声明式**路线，不落代码。
3. 会话之间不共享内存态；要跨线程，只交换 `Envelope` 与回执文件。
4. 任何“加载技能”的说法都必须落到本文件第三节的某个模块入口，否则视为没做。
5. 新增机制必须同时给出：模块路径、入口符号、一条可跑的冒烟命令。
6. 不把“仿真通过”写成“已证明”；六机制的验证一律 `evidence_class=simulated`。
7. 终裁权归人：本仓只给证据与判据，不给结论。

## 六、F 盘以往项目的基座化口径

以往项目（视频矩阵 V3、类生命经络 V3、OpenMontage 本地化、ivsa 康复工程等）进入本仓的方式统一为：

- **只读引用**：路径写进文档，代码不 import。跨盘符 import 会在 CI 上直接崩。
- **机制抽取**：把对方的机制压成一句判据 + 一个函数签名，放进 `data/` 或 `docs/`。
- **不搬正文**：对方仓库的 Markdown/CSV 一律不进本仓，避免许可混层。
- **可回滚**：任何基座化动作都要能用一个 commit 撤回，且不触碰 diff0。
