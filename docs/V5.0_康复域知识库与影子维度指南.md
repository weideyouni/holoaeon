## 一、这份文档解决什么问题

V4.6 把 12 个卡槽「只声明、不接线」摆好了位置，V5.0 要做的第一件真事是：**把康复域知识库全量入库，但一个字都不复制**。

"全量入库"在本仓的定义是 **全量登记**：每张表登记行数、字节、sha256、红线归属与只读指针；正文留在客仓（ivsa），本仓不搬运、不改写、不二次分发。这样做的原因不是省事，而是医学文字一旦被复制进另一个编号空间，就会出现"两份原文、两套口径、谁都说不清哪份是准"的经典事故。

一句话：**索引在 HoloAeon，证据在 ivsa，结论不在这里。**

## 二、第一性意图（四条，V4.6 立、V5.0 沿用）

1. **维度不变**——25 智能体 / 47 技能 / 9 域包是硬锁。任何新能力只能旁挂，不能改锁数。
2. **只声明不接线**——卡槽先占位，接线必须另出票据、过门禁、拿签字。
3. **证据不外借**——客仓证据只读互认，不复制、不顶替、不跨场外推。
4. **碳基终裁**——任何仿真、任何影子维度，都不替代人的判断；涉医输出零剂量、零诊断。

## 四、影子维度怎么用（开发者最关心的一条）

影子维度 `D_REHAB` **不是**第 13 个维度锁。它有三个硬约束：

1. `participates_in_dimension_lock = false` —— 不进 D01–D14，`check_dimension_lock.py` 不认它。
2. `affects_diff0_hash = false` —— 指纹 `2fc892cf9af6e755` 不因它变化。
3. 权重只允许 0.1–0.3，且只用于**康复域检索排序与命中解释**，不得用它改写既有 12 维度的任何结论。

用它就三步：

```python
# 1) 读索引（只读）
kb = json.load(open("data/v5_rehab_kb.json", encoding="utf-8"))
# 2) 取康复域条目
rehab = [e for e in kb["entries"] if e["layer"] in ("ivsa_data", "holoaeon")]
# 3) 排序时给个轻权重，别当硬过滤
score = base_score + 0.2 * hit_rehab(rehab, query)
```

**禁止**：把影子维度写进 `dimension_lock.json`；用它覆盖既有维度判定；把 `12 维度 + 影子` 说成 13 维度。

## 五、证据等级：解封 ≠ 上调

`EXT-EVIDENCE-01` 解封后，允许的是**流程**，不是**结论**：

- 4 张 gap 卡（`TF-M-05`、`TF-E-01/02/03`）`tier_before = tier_after = none`，`tier_unchanged = true`。
- 每张卡要上调，必须逐张满足四条：①原文可获取 ②人群/分期明确 ③参数完整 ④结局定义清晰。
- 每条上调必须在 `data/V5.0_…票据.md` 里留**具体引用**（作者、年份、期刊/登记号、页码或段落）。
- 禁止：批量上调、用同场其他模态顶替、把体外/动物结果写成人体结论、用"检索到了指南"当证据。

## 六、开发者怎么接入（五步认领法，沿用 V4.6）

1. **认领**：在票据写明 `slot_id`（如 `EXT-PROVIDER-01`）与契约原文。
2. **实现**：只加旁挂文件；不改锁数、不动他人模块、不碰 ivsa。
3. **门禁**：`v3_gate 32/32` + `unittest tests` + `tests_contract` + `redline_scan` 全绿。
4. **签字**：`weideyouni` / `潘荟丞` / 密令任一。
5. **出票**：`data/<批次>票据.md` + `reports/<批次>_check.json` + 五地同步。

三条典型路径：

- **想接新 provider**：认领 `EXT-PROVIDER-01`（Ollama，`open`）→ 装好后复跑 `live_gateway_probe --provider ollama`，判据沿用 B1–B7。
- **想扩协议**：认领 `EXT-PROTOCOL-03`（Responses/Anthropic）→ 只加 `PROTOCOL_SHAPES` 条目 + 探针分支，不覆盖已有形状，必须带计费口径。
- **想加康复知识**：**不要复制正文**。在 `v5_rehab_kb.json` 的 `entries` 里加一条登记（source / rows / bytes / sha256 / copied=false），跑 `verify_v5` D2 复算哈希即可。

## 七、故障处置

| 现象 | 首查 | 处置 |
|---|---|---|
| `verify_v5` D2 报 `:drift` | 客仓表被改动 | 重跑 `build_v5_rehab_kb.py` 再校验；不得手改哈希 |
| D3b 报维度不符 | `reports/dimension_lock.json` | 维度锁只读，先查是否自己改了锁文件 |
| D9 报卡槽未认领 | `data/extension_slots.json` | 按五步认领法补票据，不直接改 status 蒙过去 |
| D6 报剂量命中 | 索引里混入参数 | 删掉参数，只留框架与红线 |
| `tests_contract` 红 | 写序 | 先跑校验器再建清单（G9） |
