## 一、问题诊断（现状 vs 快照标杆）

### 现状（V19/V20 的 SVG）
- 189×160 纯矩形节点等距投影，无标注引线、无层次语义、无实物感
- 根因：V19 蒸馏剔除 WebGL/React（4 糟粕）后，SVG 取纯字符串拼接的最小实现；V20 只补了文字 explain，没动图像

### 快照标杆（本次 image_search 实证，见交付图）
| 标杆 | 来源 | 像样的点 |
|------|------|----------|
| 横截面标注图 | Encyclopaedia Britannica | 彩色分层 + 引线标注（barrel/refill/spring/ball…）+ 笔尖放大细节 |
| 数字编号爆炸图 | 千图网专利图 | 零件按装配顺序排布 + 数字编号 1-16 |
| 零件分类拆解图 | Allaboutlean | 白色背景 + 零件分类 + 英文标签（Tip/Grip/Spring/Barrel/Ball/Ink/Reservoir） |

### 差距四维
1. **无爆炸展开**：零件挤在一起，没有沿轴分解
2. **无标注引线**：数字/文字与零件无视觉关联
3. **无放大细节**：笔尖滚珠这类关键部位没有特写
4. **无成品对照**：没有"拆开 vs 组装好"的对照区

## 二、升级目标

概念解剖器输出"**像样的图**"，三层能力：

1. **本地确定性渲染**（纯标准库，默认）：增强 SVG —— 爆炸展开 + 引线编号 + 图例 + 成品对照
2. **生成式示意图**（联网可选）：image_search 快照参考 → image_gen/image_edit 生成 AI 示意图
3. **快照-参考-生成工作流**：一条命令完成"参考风格 → 生成示意图"

确定性底线不变：**本地 SVG 永远可用、可复现**；生成式后端是可选增强，不影响维度冻结。

## 三、架构：系列工具 + 加载协议

### （一）渲染器系列（本地确定性后端）

新建 `holoaeon/concept_anatomy_render.py`（纯标准库）：

| 渲染器 | key | 输出能力 |
|--------|-----|----------|
| 爆炸图渲染器 | render_explosion | 零件沿中轴展开 + 数字编号引线 + 底部成品对照区 |
| 标注图渲染器 | render_annotated | 横截面示意 + 引线文字标注 + 关键部位放大细节框 |
| 图例渲染器 | render_legend | 维度色语义图例 + 层次说明 |
| 结构图渲染器 | render_diagram | 现有等距投影增强版（大画布+配色+序号） |

**DESIGN_TOKENS 扩展图像 Token**（追加，不动既有 26 Token）：
```
img_style   （explosion / annotated / legend / diagram，默认 diagram）
img_palette （工业蓝 / 线稿黑白 / 全息四色）
img_axis    （垂直 / 水平展开轴）
img_annotate（true/false 引线编号开关）
img_compare （true/false 成品对照区）
```

### （二）加载协议（插件化注册）

与 packs 扩展包机制同构（旁挂注册，不进维度）：
```
RENDER_REGISTRY = { name: {fn, desc, tags} }
register_render(name, fn, desc)   # 协议：fn(anatomy, tokens) -> svg
load_render(name)                 # 按协议取渲染器
```
解剖输出经协议加载渲染器：`anatomize() → render_by_protocol(anatomy, tokens)`，默认按 `img_style` 选渲染器；未注册的 style 回落 diagram（容错）。

### （三）生成式后端（联网可选）

```
协议 snapshot：image_search 快照参考图（实体概念自动拆关键词）
协议 generate：image_gen/image_edit 以参考风格生成示意图
入口：python -m holoaeon.concept_anatomy 圆珠笔 --img schematic --generate
```
双轨并存：`--img <style>` 本地渲染（默认）；`--generate` 走生成式（需联网，输出图片 URL/文件）。

## 七、【追加】模块二：概念视觉锻造台 concept_visual_forge

> 潘老师指令（2026-11-04）：再加一个模块——**文字 → 搜索 → 初级图像描述 → 系统提示词生成 → 矩阵修改 → 优化系统提示词 → 蓝图化 / 美术化 / 艺术化**，并把这条工程路径做成"优化→创建→升级"的确定性思路。先策划，再执行。

### 7.1 模块定位

**概念视觉锻造台**：把概念解剖器的**结构化真值**（description/mechanism/components）锻造成"**可以直接出图的系统提示词**"，并支持风格矩阵批量变体与三档风格化（蓝图/美术/艺术）。与渲染器双轨互补：渲染器画本地 SVG，锻造台出"AI 能画得像样的图"的提示词。

### 7.2 能力链（八步流水线，全部确定性规则，零 LLM 依赖）

| 步 | 函数 | 干什么 |
|----|------|--------|
| 1 文字 | forge(concept_text) 入口 | 接收任意概念文字（内置/表外） |
| 2 搜索 | text_search() | CONCEPT_MAP 命中；表外概念→关键词抽取（中英分词正则）→ 相关概念匹配 → 结构化描述 |
| 3 初级图像描述 | image_desc_v1() | 主体+关键元素+布局 的初级描述（不涉及风格） |
| 4 系统提示词生成 | system_prompt_gen() | 初级描述 + 构图/配色/画风/画质 模板 → 系统级提示词 |
| 5 矩阵修改 | matrix_modify() | 风格矩阵（风格×构图×色调）批量变体 |
| 6 优化提示词 | optimize_prompt() | 负面提示词 + 质量锚点 + 确定性锚点（只画映射表内元素，防 AI 幻觉加戏） |
| 7-9 三档风格化 | stylize() | blueprint 蓝图化（工业制图）/ art_direction 美术化（设定集）/ artistic 艺术化（创作） |

### 7.3 风格矩阵（matrix_modify 的修改维度）

```
风格（6）：工业蓝图 / 手绘线稿 / 水彩 / 赛博霓虹 / 极简几何 / 油画
构图（3）：爆炸分解 / 横截面 / 场景陈列
色调（3）：冷灰蓝 / 暖米白 / 高对比黑金
```

### 7.4 工程路径（优化→创建→升级 思路）

- **现状链路**（V19/V20）：概念 → 解剖数据 → 矩形 SVG（文字多、图不像样）
- **V21 新链路**：概念 → 解剖真值 → **视觉锻造**（描述→提示词→矩阵→三档风格化）→ 本地 SVG 渲染（确定性）或 AI 生成示意图（生成式）
- **升级思路**：解剖器负责"真值"（不编造），锻造台负责"视觉翻译"（规则化），两者解耦；新模块只旁挂，不进维度、不破 diff0
