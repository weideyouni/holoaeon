> 适用版本：holoaeon V19（DOC_VERSION 0.9.16，EXTRA_PACK_ORDER 17）
> 来源：wheresryan22/anatomy（22K★，MIT）创意蒸馏 → HoloAeon 确定性实现
> 一句话：**把 HoloAeon 的抽象概念，切成"维度 / 机制 / 组件 / 验证 / 源码"的结构化解剖图**

## 一、先搞懂：这个包是干什么的

HoloAeon 里有一堆抽象词：经络、心跳机制、细胞骨架、城邦架构、去幻觉……新人第一次看到会懵——这些词背后到底是什么？

**概念解剖器就是回答这个问题的工具。** 你给它一个概念名，它按固定的十步工序，产出一份"概念解剖图"（JSON 数据，可选配 SVG 图 / HTML 页面），里面写清楚：

| 字段 | 回答的问题 |
|------|-----------|
| dimension（维度） | 这个概念属于哪一层（机制/运行时/内核/安全/学习/协议/架构/热力学/验证） |
| mechanism（机制） | 它到底靠什么实现（对应到真实模块，如 `scheduler.tick + router_layer.dispatch`） |
| components（组件） | 由哪些零件组成（真实类名/模块名） |
| verification（验证） | 怎么证明它工作（如"同输入→同结果"） |
| source（源码） | 去哪里看实现（真实文件路径） |
| audit（审计） | 解剖图本身是否自洽（四检查） |

**三个关键特点（小白必记）：**

1. **确定性**——同一个概念 + 同一份配置，永远产出同一个结果。它不是 AI 现场发挥，是从**固化映射表**里查出来的（HoloAeon 把 Anatomy 的"LLM 发明对象"改成了"确定性查找"）。
2. **可审计**——每次解剖都附带审计报告（重叠 / 穿透 / 一致性 / 确定性四检查），`all_passed` 为 true 才算解剖合格。
3. **零依赖**——纯 Python 标准库，离线可跑，不联网、不调模型。

## 三、怎么用：四个入口

### 入口 A：Python API（最推荐，小白也能上手）

```python
from holoaeon.concept_anatomy import ConceptAnatomizer, CONCEPT_MAP, DESIGN_TOKENS

# 1) 解剖一个概念（默认配置）
r = ConceptAnatomizer().anatomize("经络")

print(r["status"])                       # DONE
print(r["concept"])                      # 经络
print(r["anatomy"]["dimension"])         # mechanism
print(r["anatomy"]["mechanism"])         # topology_resonance.resonance_node
print(r["anatomy"]["component_count"])   # 8
print(r["anatomy"]["audit"]["all_passed"])  # True（四检查全过）
```

**解剖结果 `r` 的结构：**

```
r
├── concept           概念名
├── status            DONE（审计通过）/ WARN（有未知概念或审计未过）
├── anatomy           解剖图本体（JSON）
│   ├── title         概念解剖图：<概念>
│   ├── dimension / mechanism / description
│   ├── component_count / components（按深度排序）
│   ├── sort_order    组件深度排序（从最底层到最顶层）
│   ├── verification_rule / source_file
│   ├── bbox / camera / lit_component
│   ├── seal          封口密语
│   └── audit         审计报告（overlap / penetration / consistency / determinism + all_passed）
├── output            {"json": ..., "svg": "..."}（可开 html）
├── steps_completed   10
└── seal              封口密语
```

## 四、26 个设计 Token：怎么调配置

`DESIGN_TOKENS` 是 26 个配置变量，分五组。想改行为就在构造时传字典覆盖：

```python
ca = ConceptAnatomizer({"rt_theme": "light", "rt_html_enabled": True})
r = ca.anatomize("去幻觉")
print(r["output"]["html"])   # 完整 HTML 页面
```

| 组 | Token | 默认值 | 作用 |
|----|-------|--------|------|
| 运行时 rt_（6） | rt_max_components | 50 | 组件上限 |
| | rt_max_depth | 10 | 依赖深度上限 |
| | rt_audit_level | full | 审计级别（none/quick/full） |
| | rt_svg_enabled | True | 是否输出 SVG |
| | rt_html_enabled | False | 是否输出 HTML 页 |
| | rt_theme | dark | 主题（dark/light/paper/blueprint） |
| 审计 audit_（5） | audit_overlap_threshold | 0.1 | 重叠判定阈值 |
| | audit_penetration_check | True | 穿透检测开关 |
| | audit_consistency_check | True | 一致性检测开关 |
| | audit_golden_compare | False | golden 比对开关 |
| | audit_max_pairs | 10000 | 最大审计对数 |
| 输出 out_（5） | out_format | json | json/svg/html/all |
| | out_indent | 2 | JSON 缩进 |
| | out_include_audit | True | 输出含审计报告 |
| | out_include_metadata | True | 输出含元数据 |
| | out_seal | 潮起开门，潮落闭嘴 | 封口密语 |
| 验证 verify_（5） | verify_diff0 | 2fc892cf9af6e755 | diff0 期望值 |
| | verify_selftest | 25/25 | selftest 期望 |
| | verify_extra_pack_order | 17 | 扩展包数期望 |
| | verify_version | 0.9.1 | VERSION 期望 |
| | verify_doc_version | 0.9.16 | DOC_VERSION 期望 |
| 全息 holo_（5） | holo_meridian / holo_heartbeat / holo_skin / holo_hebbian / holo_city | — | 五机制映射声明 |

**四个最常见的场景：**

```python
# 场景1：要交互 HTML 页面
ConceptAnatomizer({"rt_html_enabled": True})

# 场景2：要浅色主题
ConceptAnatomizer({"rt_theme": "light"})

# 场景3：要时间戳留痕（默认不开，开了会破坏确定性）
ConceptAnatomizer({"out_timestamp": True})

# 场景4：只要 JSON，不要 SVG
ConceptAnatomizer({"rt_svg_enabled": False})
```

> **时间戳说明**：默认不写入时间戳——这是刻意的。保证"同概念 + 同 Token → 同解剖图"（确定性优先）。只有你显式开 `out_timestamp` 才会带时间戳。

## 五、扩展包：5 技能 / 3 角色 / 1 工作流

第 17 个扩展包 `concept_anatomy`，挂在 `packs/__init__.py` 的 EXTRA_PACK_REGISTRY（不进 PACK_ORDER，25/47/9 维度不动）：

**5 个技能**（都是模块级函数，可直接调用）：

| 技能 | 干什么 | 示例 |
|------|--------|------|
| anatomy_concept | 概念解剖（十步工序） | `anatomy_concept("经络")` → status=DONE |
| anatomy_audit | 深度审计（四检查） | `anatomy_audit("经络")` → all_passed=True |
| anatomy_svg | 等距投影 SVG | `anatomy_svg("城邦架构")` → has_svg_tag=True |
| anatomy_map | 查概念映射表 | `anatomy_map("去幻觉")` → mechanism=dehallucination... |
| anatomy_tokens | 查 26 个 Token | `anatomy_tokens()` → token_count=26 |

**3 个角色：** anatomist（解剖师）· auditor（审计师）· cartographer（制图师）

**1 个工作流：** full_anatomy = 取映射 → 十步解剖 → 深度审计 → 渲染 SVG

```python
from holoaeon.packs.concept_anatomy_pack import anatomy_concept, anatomy_audit, anatomy_svg

print(anatomy_concept("经络")["status"])      # DONE
print(anatomy_audit("经络")["all_passed"])    # True
print(anatomy_svg("城邦架构")["svg_length"])  # 输出 SVG 字符数
```

## 六、常见问题 FAQ

**Q1：输入了不存在的概念会怎样？**
不会崩。两种返回（注意区别）：
- 直接调 `anatomize()` → `{"error": "未知概念: xxx", "available": [10 个概念]}`（**没有** status 字段）；
- 调扩展包技能 `anatomy_concept()` → `{"status": "WARN", "error": ..., "available": [...]}`（技能层包装了 WARN）。

**Q2：怎么添加新概念？**
编辑 `holoaeon/concept_anatomy.py` 的 `CONCEPT_MAP`，按现有条目格式加一项（dimension / mechanism / description / components / verification / source），即可被解剖器识别。

**Q3：为什么两次解剖结果一模一样？**
这是特性不是缺陷。步骤 3"发明映射"不是 LLM 现场发明，而是从固化映射表**确定性查找**，且时间戳默认关闭——保证可复现、可对账。

**Q4：audit 的 all_passed 代表什么？**
四检查全部通过：overlap（无重叠组件）、penetration（深度单调非增，无穿透）、consistency（组件字段完整）、determinism（确定性映射）。全过 → status=DONE。

**Q5：SVG / HTML 是什么样？**
SVG 是等距（30°）投影的组件方块图，纯字符串生成、无 DOM 库，深色主题默认（组件上限 50 内）。HTML 是内嵌该 SVG 的简单页面，默认关闭。

**Q6：这套东西联网吗？要装依赖吗？**
不联网、零第三方依赖（纯标准库）。完全离线确定性运行。
