
## 四、自写回执（A10）的处置口径

- 判据：`reports/*.json` 从 `five_site_dna.REPO_FILES` 派生候选，产生者从 `scripts/{verify_,build_,check_,gen_}*.py` 回填文件名得到；派生为空时退回 `LEGACY_SELF_REPORTS` 并标 `self_derive="legacy"`（fail-loud，不静默）。
- 排除范围：**只排除 `changed` / `new`**；`missing` 不排除——删回执是真实退化，必须判红。
- 差分证据：每条被排除项记录 `owner` + `prev_sha16` + `curr_sha16`，回执被意外改写仍留痕，只是不再单独判红（该职责由该回执的 owner 校验器自身承担）。
- **新增写型校验器时无需改 A10**：只要它写的是 `reports/*.json` 且脚本名以 `verify_/build_/check_/gen_` 开头，下次跑 A10 自动纳入。

## 五、五地同步（同对象同 hash）

| 站 | 动作 | 回读方式 |
|---|---|---|
| S1 本地 | `git commit` | `git rev-parse HEAD` |
| S2 Gitee（权威） | `git push HEAD:main`（内联令牌，输出须 `.Replace($tk,"***")`） | `git ls-remote`，延时 12–20 s |
| S3 GitHub | `git push origin HEAD:main` | `git ls-remote`，延时 12–20 s |
| S4 向量海 | 新增号段 → copy `SHA256SUMS` 到 `74_SHA256SUMS` → `build_vector_sea_manifest.py --dir <S4>` | `check()` → `PASS` + `sums_74_in_sync=True` + `bad_sha256=[]` |
| S5 HF | `python scripts\mirror_hf.py --base <旧短sha> --head <新短sha>` | `sha` + `remote_files` + `mismatch=[]` |

**顺序铁律**：向量海必须「换号段 → 换 74 → 建 manifest」，颠倒会让 `74_SHA256SUMS` 自指 `bad_sha256`；建 manifest 必须用 `build_vector_sea_manifest.py`，手写 `listdir` 版本会漏哈希。

**回执**：`_holoaeon_v4_five_site_receipt_20261102.json` + `_receipts\..._<批次>.json` 副本，字节相同；回执**不入 git**。刷新范式：`dict(old)` 铺底 + `update`；`files` 取自向量海 `manifest.json`；`history` 过滤用 `isinstance(h, dict)` 守卫。

## 六、失败处置（不得静默）

| 现象 | 根因 | 处置 |
|---|---|---|
| `test_11_sums_match_recorded_digest` FAIL | 写型校验器事后改了摘要 | 重跑第 5–8 步，不改测试 |

## 七、批次命名与版本

- 批次：`V<主>.<次>-B<n>`（如 `V6.0-B1`、`V6.1-B2`），一次交付一个批次号。
- `spec.VERSION` 冻结不动；`DOC_VERSION` 每批 +0.1（当前 `0.9.6`）。
- 提交：内容提交在前、清单不动点提交在后（后者只在「跑完校验又改了摘要」时产生）。
- 提交信息模板：`<批次> <主题>：<三到五个动作>（维度不变 25/47/9）`。
