# 架构详解

本文档说明 HoloAeon 的分层架构、设计取舍与数据流。

## 1. 设计哲学：自底向上

HoloAeon 的每一层都建立在其下层可独立验证的原语之上：

```
领域包（Domain Packs）          ← 业务能力组合
        │
内核门面（Kernel）              ← 统一入口 / 编排
        │
调度器（Scheduler）  守卫（Guard）  记忆（Memory）
        │
自适应协作图（AdaptiveGraph）
        │
总线（Bus） + 信封（Envelope）
        │
智能体（Agent） + 技能注册表（SkillRegistry）
        │
超向量（Hypervector）  模型适配（ModelAdapter）  集群（Cluster）
```

这种分层的核心好处是：**任何一层都可以单独测试、单独替换、单独理解**。

## 2. 数据如何流动

一次任务提交（`Kernel.submit`）的完整路径：

1. **构造信封**：任务文本与额外参数打包为 `Envelope`，附带权限元数据。
2. **解析目标**：`to` 为 agent_id / 列表 / None（自动选择）。
3. **守卫检查**：`Guard.inspect` 逐层出 Verdict，命中危险模式则拦截。
4. **智能体处理**：`Agent.handle` 选择最匹配技能，按签名绑定参数并调用。
5. **记忆写入**：任务与结果写入三层记忆。
6. **返回聚合结果**：含 `all_ok`、逐目标结果与运行时 ID。

## 3. 关键设计取舍

### 逻辑矩阵 vs 物理矩阵
1331×1331 是**逻辑坐标空间**，不是实际分配的二维数组。构造时零预分配，节点按需稀疏激活。
这避免了"先分配大矩阵"与"稀疏激活"的自相矛盾。

### 正交机制
- 同步 → 调度器（Scheduler）
- 安全 → 守卫（Guard）
- 路由 → 总线（Bus）
- 学习 → 协作图（AdaptiveGraph）
- 支撑 → 记忆（Memory）

每个机制职责单一，不重叠。

### 确定性
所有随机性都来自确定性种子（如 `hashlib.sha256` 派生），给定相同输入必然产生相同输出。
这使框架可复现、可审计、可对比。

## 4. 并发模型

- **总线**：线程安全（`RLock`），支持多线程发布订阅。
- **集群**：智能体作为带邮箱的 Actor，在屏障后并发执行，结果可重复。
- **记忆**：所有读写加锁。

## 5. 模式标记

所有消息与回执都带 `mode` 字段，默认为 `simulated`。这明确区分了"真实外部调用"与"本地
仿真"，避免把仿真结果误当作真实证据。
