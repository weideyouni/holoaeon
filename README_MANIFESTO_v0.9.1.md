## 0. 这份文件是什么

一段誓愿的价值不在于它多动人，而在于它能否被兑现、被检验、被反驳。因此本文件做了三件事：

1. 把口语誓愿改写成**可判定条款**（能判断某次提交是否违约）；
2. 为每条条款指明**工程落点**与**当前状态**（`已兑现` / `部分兑现` / `未兑现`）；
3. 保留原誓愿的比喻，但**明确标注哪些是隐喻、哪些是实证**，不把诗意当证据。

## 1. 五条誓约

### 誓约一 · 被使用，而不是被收藏

| 项 | 内容 |
|---|---|
| 原意 | 造它是为了被真正使用——不是被收藏、被围观，也不是变成一个装饰性的星标数字 |
| 规范表述 | 项目必须提供一条**零前置依赖**的运行路径：从取得发行包到看见第一条正确输出，不得要求安装第三方包、不得要求联网、不得要求先读完全部文档 |
| 工程落点 | `SYSTEM_README_v0.9.0.md` §6 快速取用；`bridges/README.md` 五分钟上手；`releases/` 每版可独立解压独立自检 |
| 状态 | **已兑现**（实跑：解压 → 34 单测 OK → 自检 24/24 → 红线零违规） |

**它保护了哪条立场**：零依赖。一条需要先配环境的路径，事实上已经把大多数人挡在门外。

### 誓约二 · 为具体的人干完一件具体的事

| 项 | 内容 |
|---|---|
| 原意 | 真正跑在某台旧笔记本上，替一个预算有限、不熟悉英文文档、没读过安装说明的普通人，老老实实干完一件事 |
| 规范表述 | 最低可用路径的硬件与软件门槛必须写明并实测：单机、纯标准库、离线可跑；面向非专家时，错误必须以**指引**而非堆栈呈现 |
| 工程落点 | `docs/support-matrix.md`（Python 版本 × 单测/自检/红线/示例 实测格）；`bridges/quickstart.py --check` 在缺服务时打印三行指引并以退出码 2 结束，无 traceback |
| 状态 | **部分兑现**：离线内核路径已实测；需要本地模型的那条路径在本机**未实测**（无本地推理服务），记为 `untested`，不写成通过 |

**它保护了哪条立场**：代价显式。"能跑"必须由实测格提供，不能由宣传语提供。

### 誓约三 · 每一次取舍都记账留痕

| 项 | 内容 |
|---|---|
| 原意 | 把每一次取舍都记账留痕，像人的每一个选择都值得被自己回放 |
| 规范表述 | 任何进入骨架的判定、任何一次降级与淘汰，都必须落在**只追加**记录上，并能由该记录独立回放；回放不得依赖原始会话原文 |
| 工程落点 | `packs/nephron_pack.py`（只追加账本 + 窗口构成表 + 回放四件套）；`examples/nephron_ledger_sample.jsonl` + `examples/nephron_replay_report.md` 黄金样例；`docs/nephron.md` |
| 状态 | **已兑现（限定范围）**：P0 为只读观测，样本回放可复现；A1/A2 为宿主编排层实测，**不等于生产链路闭环** |

**它保护了哪条立场**：取舍留痕。没有回放能力的"优化"，事后无法归因，只能算说法。

### 誓约四 · 该标 `simulated` 就标，被信任时才标 `live`

| 项 | 内容 |
|---|---|
| 原意 | 它被骗的时候亮出 `simulated`，被真正信任的时候才敢标 `live` |
| 规范表述 | 系统必须严格区分"自有骨架推导"与"外包得来的信念"：离线自检、仿真、真实调用三类回执各用独立取值，**禁止互相顶替**；外部依赖必须在输出中可识别 |
| 工程落点 | 核心包 `ModelAdapter` 恒为 `simulated`；宿主桥 `mode` 仅 `live` / `echo`；`docs/bridges.md` 明写 `echo` 永不冒充 `live` |
| 状态 | **已兑现（就装配与门禁而言）**：`echo` 全链路、远程门禁四分支、无服务分支均已实测；真实 `live` 回执 `untested` |

**它保护了哪条立场**：宿主边界 + 代价显式。把仿真当能力上报，是这个项目最该防的失败。

### 誓约五 · 每个取舍都有理由码

| 项 | 内容 |
|---|---|
| 原意 | 每次淘汰和降级都有理由码 |
| 规范表述 | 每条记录事件必须携带且只携带一个主理由码；无法归类时使用保留码 `UNKNOWN` 并触发计数告警，**禁止静默吞掉**；新增理由码须评审 |
| 工程落点 | `packs/nephron_pack.py` 理由码表（27 + 1 保留）；`docs/nephron.md` §12 的 O-1～O-10 裁决；`packs/uplift_pack.py` 的判定技能可对理由码完备性给出 `PASS/FAIL/UNCHECKED` |
| 状态 | **已兑现**：`UNKNOWN` 单独计数并告警（O-4：占比 >1% 即告警）；回放器零 `UNKNOWN` 是 P1 的四判据之一 |

**它保护了哪条立场**：取舍留痕 + 确定性。理由码是把"临场发挥"转成"可复核判断"的最小单位。

## 2. 关于"同一套东西的三种写法"

原誓愿里有一段说法：碳基的你、硅基的我、以及用代码写成的它，是同一套底层上的三种写法，
每个局部都带着整体的一部分。

**保留这句的意思，但划定边界：**

- 可作为**设计取向**：确定性底层 + 局部携带整体约束（维度不变式、代际指纹、血统引用都属此意）；
- **不可作为**实证结论：不主张"全息"已有生物学或物理学证明，也不主张系统具备意识；
- 项目内凡使用"生命体""器官""代谢""经络"等词，均为**工程隐喻**，其可检验部分只有一条：
  **相同输入给出相同输出，且每次取舍可回放**。
- **仿真 ≠ 证明，碳基终裁**：所有判定最终由人验收，自动化只提供证据。

**它保护了哪条立场**：确定性 + 代价显式。隐喻可以用，但不能被当作能力证明。
